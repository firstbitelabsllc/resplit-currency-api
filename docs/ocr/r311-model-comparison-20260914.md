# Receipt model comparison — 2026-09-14

## Decision

Keep the current production provider. Standard Astra and Fast Astra are close on correctness, and neither earns a production switch on this evidence. Fast reduced measured API scan latency by 22.9% at p50 and 13.6% at p95, for about 2.08× the estimated token cost. Standard had one more exact receipt total; Fast had one more exact item count. The paired results do not show a clear accuracy winner.

Fast is a service tier on the same `gpt-6-astra` model, not a separate “Astra Light” model. The API returned the requested `default` and `fast` tiers for all 77 provider-started calls in this run. The fast-tier cost premium is real; its latency benefit here is materially smaller than 2×. Keep it available for measured, latency-sensitive experiments, but leave production configuration unchanged.

No output repair was added. The scorer compares ordered item-name and amount sequences; it never rejoins names, associates nearby text with amounts, fills nulls, or changes model output. This specifically honors the concern about language-fragile nearest-character matching.

## Missing and printed-zero amounts

Across the provider-started ground truth there is one item with an absent or unreadable amount and 19 items with a printed zero. The model returned zero unknown amounts for both tiers; it returned 16 zero-valued amounts per tier. Because the sequence metric does not link an individual name to its amount, the 16 outputs cannot be presented as 16 correct reads of the 19 printed zeros. The one expected unknown was not preserved as null in either tier.

The shared prompt already states that a printed zero is `0`, a missing or unreadable amount is `null`, and the model must not invent values to balance the total. Schema-valid JSON did not make that extraction correct. A prompt change remains an experiment to validate on the same paired corpus; this result does not establish that stricter wording alone will fix the failure.

## Latency and cost scope

`API scan-leg` p50/p95/max is measured after the shared image bytes are available and includes all 77 provider-started calls. There were no failed provider calls in this run. The separate post-read runner-wall row includes all 85 attempts, including the eight 0–1 ms pre-provider rejections; it excludes the one shared fixture read per image. Shared local fixture-read p50/p95/max was 3.39/6.78/1,019.61 ms. None of these is full native-app latency: this run does not measure the iOS image-preprocessing, upload, or saved-receipt reopen.

Cost is a usage-based estimate from recorded token counts and the checked-in Astra rates, not a billing receipt. The current [GPT-6 Astra API pricing](https://developers.openai.com/api/docs/models/gpt-6-astra) lists $10 per million input tokens, $1 cached input, and $50 output, with Fast priced at 2× applicable rates. Observed cost is therefore about $3.45 standard and $7.18 fast for this corpus; amounts can vary with image detail, output tokens, caching, and later rate changes.
